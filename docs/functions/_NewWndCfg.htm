_NewWndCfg

Creates a window dimension config map with the layout metrics used to position the header, footer separator and content area.

_NewWndCfg([$iWidth = $WIN_WIDTH [, $iHeight = $WIN_HEIGHT [, $iFooterSepY = $FOOTER_SEP_Y [, $iHeaderHeight = $HEADER_H [, $iContentTop = $CONTENT_TOP [, $iContentWidth = $CONTENT_W]]]]]])

Parameters

$iWidth[optional] Window width in pixels. Default is $WIN_WIDTH (540).
$iHeight[optional] Window height in pixels. Default is $WIN_HEIGHT (345).
$iFooterSepY[optional] Y position of the footer separator line. Default is $FOOTER_SEP_Y.
$iHeaderHeight[optional] Height in pixels of the header band. Default is $HEADER_H (70).
$iContentTop[optional] Y position where page content begins, below the header. Default is $CONTENT_TOP.
$iContentWidth[optional] Width available to page content. Default is $CONTENT_W.

Return Value

SuccessA map with keys iWidth, iHeight, iFooterSepY, iHeaderHeight, iContentTop, iContentWidth, all coerced to Int(). iFooterSepY and iContentWidth are recalculated against a non-default $iHeight/$iWidth unless explicitly overridden, and likewise iContentTop against a non-default $iHeaderHeight.

Remarks

This is the first of the small "part" config constructors. The map it returns is combined with a font config and a button config by _NewInstallerCfg() into the single flat config map that every page-template and layout function in the library reads from. Each parameter corresponds directly to one of the library's own layout constants ($WIN_WIDTH, $HEADER_H, etc.), so a caller can override exactly one dimension - say a taller window - without reconstructing the rest of the layout by hand.

Related

_NewFontCfg, _NewBtnCfg, _NewInstallerCfg

Example

; Wider window - iContentWidth adjusts automatically, other dimensions stay at their defaults
Local $mWndCfg = _NewWndCfg(640)
Local $mCfg = _NewInstallerCfg($mWndCfg)
